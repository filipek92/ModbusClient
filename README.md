# Modbus Client

This is a Modbus client application built with Quasar, Vue 3, TypeScript, and Tauri (Rust backend). It allows you to connect to Modbus devices, read and write data, and manage devices.

## Technologies Used

*   **Quasar Framework:** A high-performance Vue.js framework for building responsive UIs.
*   **Vue.js 3:** A progressive JavaScript framework for building user interfaces.
*   **TypeScript:** A typed superset of JavaScript that compiles to plain JavaScript.
*   **Tauri 2:** Lightweight desktop shell using the system WebView and a Rust backend.
*   **Pinia:** A state management library for Vue.js.
*   **tokio-modbus / tokio-serial:** Modbus TCP, RTU and RTU over TCP communication in Rust.

## Project Structure

*   `src`: Contains the Vue.js application source code.
    *   `assets`: Static assets like images and fonts.
    *   `boot`: Quasar boot files (`tauri-api.ts` exposes the backend as `window.myAPI`).
    *   `components`: Vue components.
    *   `css`: CSS and SCSS files.
    *   `decoders`: Decoders for different Modbus devices.
    *   `layouts`: Layout components.
    *   `pages`: Page components.
    *   `router`: Vue Router configuration.
    *   `stores`: Pinia store modules.
*   `src-tauri`: The Rust backend.
    *   `src/modbus.rs`: Connections, reads/writes, device and value scanners.
    *   `src/decoders.rs`: Default + user decoder files, import/export, decoder packs.
    *   `src/updater.rs`: Auto-update from GitHub Releases.
    *   `resources/default-decoders`: Decoders bundled with the app.
    *   `tauri.conf.json`: Window, bundling and updater configuration.
*   `public`: Static assets that are not processed by Vite.

## Prerequisites

*   Node.js and npm
*   Rust (stable) – <https://rustup.rs>
*   Linux only: `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev libudev-dev patchelf`

## Available Scripts

*   `npm run dev`: Starts the app in development mode (Quasar dev server + Tauri window).
*   `npm run build`: Builds release bundles into `src-tauri/target/release/bundle/` (AppImage + deb on Linux, NSIS installer on Windows).
*   `npm run lint`: Lints the frontend code.
*   `npm test`: Runs the Rust backend tests.

## Main Features

*   **Connection Settings:** Modbus TCP, RTU (serial) and RTU over TCP.
*   **Device Manager:** Add, remove, and manage Modbus devices.
*   **Manual Query:** Manually send Modbus queries to a device.
*   **Regular Collectors:** Set up regular data collection from devices.
*   **Log Console:** View logs from the application and the Modbus communication.
*   **Auto Updates:** Checks for and installs signed updates from GitHub Releases.

## Releasing

Pushing a `vX.Y.Z` tag runs `.github/workflows/build.yml`, which builds Linux and Windows bundles and publishes them, together with `latest.json` for the updater, to GitHub Releases.

Update packages must be signed. The repository needs these secrets:

*   `TAURI_SIGNING_PRIVATE_KEY` – content of the private key generated by `npx tauri signer generate`
*   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` – its password (empty if none)

The matching public key is in `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`). Losing the private key means existing installations can no longer verify updates.
